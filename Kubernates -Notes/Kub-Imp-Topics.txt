What is Node Affinity?

Node Affinity means scheduling a Pod on a particular node based on that node's labels.

Example:

Imagine your Kubernetes cluster has 3 worker nodes:
- Node 1: SSD
- Node 2: HDD
- Node 3: SSD
You want your Java application to run only on SSD nodes.

You can use Node Affinity.

=============================
Types of Node Affinity
==================================

1. requiredDuringSchedulingIgnoredDuringExecution  ---: Must match the condition. Otherwise, Pod won't be scheduled.

2. preferredDuringSchedulingIgnoredDuringExecution---: Try to match the condition, but scheduling can happen on another node.

Required = Mandatory.

Preferred = Optional preference.


Example-2:

Schedule Java application Pods only on nodes having disktype=ssd.


Step 1: Label a worker node.

kubectl label nodes worker-node-1 disktype=ssd


Step 2: Create deployment.yaml.



apiVersion: apps/v1
kind: Deployment
metadata:
  name: java-web-app
  namespace: ashokit-ns
spec:
  replicas: 2
  selector:
    matchLabels:
      app: java-web-app
  template:
    metadata:
      labels:
        app: java-web-app
    spec:
      affinity:
        nodeAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
            nodeSelectorTerms:
              - matchExpressions:
                  - key: disktype
                    operator: In
                    values:
                      - ssd
      containers:
        - name: java-container
          image: naniom1234/javawebapp:v1
          ports:
            - containerPort: 8080

kubectl apply -f deployment.yaml

kubectl get pods -o wide -n ashokit-ns

kubectl describe pod <pod-name> -n ashokit-ns


Operator	Meaning

In		Value must be in the given list
NotIn		Value must not be in the list
Exists		Label key must exist
DoesNotExist	Label key must not exist
Gt		Value must be greater than
Lt		Value must be less than

Interviewer: What is the difference between Node Selector and Node Affinity?
- Node Selector: Simple key-value matching.
- Node Affinity: Advanced scheduling rules with required and preferred conditions, and multiple operators.

ConfigMap:
=============

ConfigMap is used to store application configuration data separately from application code and container images.


For example, your Java Spring Boot application needs:
- Database URL
- Application environment
- Log level
- Application port
Instead of hardcoding these values inside your application, you can store them in a ConfigMap.



2. Real-time example
Imagine your application connects to a MySQL database.

Without ConfigMap:

DB_URL=jdbc:mysql://localhost:3306/ies


The configuration is inside your application.


With ConfigMap:

ConfigMap
DB_URL, DB_NAME, LOG_LEVEL

Java Spring Boot Pod
Reads configuration values

Application runs using those configurations


=================
3. Create ConfigMap YAML
File: configmap.yaml
=========================
apiVersion: v1
kind: ConfigMap

metadata:
  name: springboot-config
  namespace: ashokit-ns

data:
  DB_URL: "jdbc:mysql://mysql-service:3306/ies"
  DB_NAME: "ies"
  LOG_LEVEL: "INFO"


kubectl apply -f configmap.yaml




kubectl get configmap -n ashokit-ns

kubectl describe configmap springboot-config -n ashokit-ns


4. How to use ConfigMap in Deployment?
You can inject ConfigMap values into containers as environment variables.


apiVersion: apps/v1
kind: Deployment

metadata:
  name: springboot-app
  namespace: ashokit-ns

spec:
  replicas: 2

  selector:
    matchLabels:
      app: springboot-app

  template:
    metadata:
      labels:
        app: springboot-app

    spec:
      containers:
        - name: springboot-container
          image: naniom1234/javawebapp:v1

          envFrom:
            - configMapRef:
                name: springboot-config



What is ConfigMap in Kubernetes?

"ConfigMap is a Kubernetes object used to store non-sensitive configuration data separately from application code. 
We can inject these configurations into containers using environment variables or mount them as files. 
This helps us manage configurations across different environments without rebuilding Docker images."
