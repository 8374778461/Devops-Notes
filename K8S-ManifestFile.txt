apiVersion: apps/v1
kind: Deployment
metadata:
  name: java-app
spec:
  replicas: 3

  selector:
    matchLabels:
      app: java-app

  template:
    metadata:
      labels:
        app: java-app

    spec:
      containers:
      - name: java-container
        image: nginx:latest
        ports:
        - containerPort: 80



	When Deployment YAML is applied, Kubernetes creates a Deployment object. Deployment internally creates a ReplicaSet. The ReplicaSet reads the replica count and creates the required Pods using the Pod template. The selector in ReplicaSet matches the labels defined in the Pod template, so ReplicaSet can identify and manage its Pods. If any Pod is deleted or fails, ReplicaSet automatically creates a new Pod to maintain the desired count.

================
Pod Life Cycle 
===============


Pod YAML
   ↓
API Server receives request
   ↓
Pod Object created in Kubernetes
   ↓
Scheduler finds a suitable Worker Node
   ↓
Pod assigned to that Node
   ↓
Kubelet on the Node receives instruction
   ↓
Container Runtime (Docker/containerd) pulls image
   ↓
Container is created
   ↓
Application starts
   ↓
Pod becomes Running

===========
Deamon Set
==========
DaemonSet is a Kubernetes controller that ensures one Pod runs on every worker node.


3 Nodes
   ↓
DaemonSet
   ↓
3 Pods


5 Nodes
   ↓
DaemonSet
   ↓
5 Pods
