=============
1. API Server:
==============

 API Server is the entry point of the Kubernetes cluster
We communicate with the API Server using kubectl.
It receives requests from users.
It validates and processes requests.
It stores cluster state in ETCD.

API Server receives your request, validates it and stores the Deployment information in ETCD.

ETCD stores something like:
Information	Value
Application	Java App
Desired replicas	3
Current replicas	0

This is the desired state: 3 Pods should be running.


==============
2. Scheduler
============

   - Assigns pods to worker nodes.

Scheduler watches the API Server for newly created Pods that don't have a node assigned.
It identifies a suitable worker node.
It considers CPU, memory, resource requests, taints, tolerations and affinity
It informs the API Server about the selected node.

==========================
3. Controller Manager
===========================
Continuously monitors the cluster.
Checks the desired state against the actual state.
Takes corrective action if they don't match..

You create a Deployment with 3 replicas.
replicas: 3

Suppose one Pod fails
Controller Manager ensures the desired state is maintained by coordinating the relevant controllers, which request a replacement Pod through the API Server.

==============
4. ETCD
==============

- ETCD is a distributed key-value database.
- Stores Kubernetes cluster information.
- Stores configuration, desired state and cluster state.
- API Server communicates with ETCD to read and write data.
Example: Deployment information, Pod information, Configurations and Secrets.

Kubernetes Cluster = Company

API Server        = Receptionist
Scheduler         = Team Lead (assigns work)
Controller Manager= Manager (checks work is completed)
ETCD              = Company Database

========================
Docker Vs Containered :
====================

Docker is a complete container platform used by developers,
whereas containerd is the container runtime that actually
creates and manages containers. Docker internally uses
containerd, and Kubernetes communicates directly with
containerd through CRI.

Docker → containerd → runc → Container
Kubelet → CRI → containerd → runc → Container


Q: What is the difference between Docker and containerd?

"Docker is a container platform used to build, package, distribute and run containerized applications. 
containerd is a container runtime responsible for managing the container lifecycle, such as pulling images, creating and starting containers.
 Kubernetes can communicate directly with containerd through CRI without requiring Docker Engine."

Docker
Docker helps us:
1. Build – Build Docker images.
2. Package – Package application and dependencies into images.
3. Run – Run containers.
4. Distribute – Push and pull images from registries.


containerd
containerd directly manages the container lifecycle:
1. Pull images.
2. Create containers.
3. Start containers.
4. Stop containers.
5. Manage container execution

ctr means Containerd CLI (Command Line Interface)

Docker Runtime      → docker command
Containerd Runtime  → ctr command

Docker

docker images
docker ps
docker run nginx

Containerd

ctr images ls
ctr containers ls

ctr is the native command-line tool for containerd. It is used to pull images, create containers, and manage containerd directly.

containerd = Runtime installed on worker node

ctr = CLI used to access containerd

CRI = Interface used by Kubelet to access containerd

crictl = CLI used to access containerd through CRI

containerd is the software that actually pulls images, creates containers, starts containers, stops containers, and manages containers.

kubectl  → Manage Kubernetes resources

CRI      → Bridge between Kubelet and containerd

containerd → Container Runtime

ctr      → Directly manage containerd

crictl   → Troubleshoot containerd through CRI




You can explain it like this:
- kubectl: Used to communicate with the Kubernetes API Server and manage cluster resources.
- ctr: Used to communicate directly with containerd.
- crictl: Used to communicate with a CRI-compatible container runtime for debugging and inspecting containers.


Command	       Communicates with	                        Purpose
kubectl	         Kubernetes API Server	            Manage cluster resources
ctr	  	      containerd                 Direct  containerd operations
crictl		      CRI runtime endpoint           Debug Pods and containers

crictl pods

crictl ps -a

crictl images

# Check containerd containers
ctr containers list
