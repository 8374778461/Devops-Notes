===
chart.yaml
===

Chart.yaml is the metadata file of a Helm chart.
 It contains chart name, chart version, application version, description, and chart type. Helm reads this file to identify and manage the chart.

apiVersion: v2
name: myapp
version: 1.0.0
appVersion: "1.0"

========
Values.yaml
=======
values.yaml = variables file in Helm.

Instead of hardcoding values in templates, we keep them in values.yaml.

values.yaml stores configurable values such as image name, image tag, replica count, service type, and ports. 
Templates access these values using {{ .Values.<variable> }}. This allows the same Helm chart to be deployed across Dev, QA, and Prod environments with different configurations.

Example :


replicaCount: 2

image:
  repository: nginx
  tag: latest

service:
  type: ClusterIP
  port: 80

templates/deployment.yaml
======================

apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ .Release.Name }}-nginx
spec:
  replicas: {{ .Values.replicaCount }}
  selector:
    matchLabels:
      app: {{ .Release.Name }}-nginx

  template:
    metadata:
      labels:
        app: {{ .Release.Name }}-nginx

    spec:
      containers:
      - name: nginx
        image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"

        ports:
        - containerPort: 80


==================
templates/service.yaml
=========================

apiVersion: v1
kind: Service
metadata:
  name: {{ .Release.Name }}-nginx

spec:
  type: {{ .Values.service.type }}

  selector:
    app: {{ .Release.Name }}-nginx

  ports:
  - port: {{ .Values.service.port }}
    targetPort: 80
    protocol: TCP

helm-charts/

What is inside index.yaml?

apiVersion: v1
entries:
  myapp:
  - version: 1.0.0
    urls:
    - myapp-1.0.0.tgz

This file tells Helm:


Available Chart : myapp
Version         : 1.0.0
Package         : myapp-1.0.0.tgz


index.yaml is like a catalog of available charts.
