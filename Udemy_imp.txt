Manually We add node  to pod using:

There are two manual ways to schedule a Pod:
1. Set nodeName in the Pod manifest at creation time (simplest).
2. Create a Binding for an already-created Pod (mimics what the scheduler does).



Option 1 — Set nodeName in the Pod manifest (creation time)-->it is used for creation time

nodeName: node02  in Spec

    - containerPort: 8080

kubectl apply -f pod.yaml

Step 2: What does Scheduler do?
Scheduler checks:
- Is Node 1 healthy?
- Is Node 2 healthy?
- Is Node 3 healthy?


Suppose all three are healthy and have no other scheduling restrictions.

All three nodes are eligible.



Step 3: How does it select?
Scheduler scores the three nodes using its scheduling rules.

For example, suppose the scores are:

Node	Score (illustrative)
Node 1	60
Node 2	80
Node 3	50

Scheduler selects Node 2 because it has the highest score in this example.

Taints and Tolerants
======================

"Taints and tolerations are used to control which Pods can be scheduled on particular worker nodes.
 Taints are applied to nodes, and matching tolerations are added to Pods. This helps us dedicate nodes for specific workloads."



Taint = Node restriction.

Toleration = Pod permission to tolerate that restriction.




1. NoSchedule – Don't allow new Pods


kubectl taint nodes node01 app=payment:NoSchedule


Node 1

nginx Pod

Java Pod

Existing Pods are not automatically removed.
Remember: New Pods without toleration cannot be scheduled. Existing Pods continue running.


2. PreferNoSchedule – Try to avoid

kubectl taint nodes node01 app=payment:PreferNoSchedule

Meaning: Node 1 says, "Please avoid placing Pods here if possible, but if there is no better option, you can schedule them."

Remember: It is a preference, not a strict restriction.

3. NoExecute – Don't allow and remove existing Pods


kubectl taint nodes node01 app=payment:NoExecute
Remember: NoExecute affects both existing and new Pods.


4. Easy comparison
Effect		New Pods	Existing Pods
NoSchedule	Blocked		Continue running
PreferNoSchedul Try to avoid	Continue running
NoExecute	Blocked		Evicted
