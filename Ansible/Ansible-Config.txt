Inventory File
    ↓
Contains target servers

ansible.cfg
    ↓
Contains default settings
    (inventory location,
     default user,
     SSH settings)


Inventory file contains the target/managed nodes on which tasks are executed. ansible.cfg is used to define default settings such as inventory path, default remote user, host key checking, etc., for connecting and managing those nodes. ✅


so with out using ansible .cnfg file every time we use inventory file and -u 

If you don't use ansible.cfg, then every command must explicitly tell Ansible:

Which inventory file to use (-i inventory)
Which user to connect as (-u bob)

Example:


ansible web -i inventory -m ping -u bob -k

-i inventory → use inventory file
-u bob → login as bob
-k → ask for password

==================
Without ansible.cfg

Every command:

ansible web -i inventory -m ping -u bob -k

ansible web -i inventory -m copy -a "src=f1.txt dest=/tmp/app.conf" -u bob -k

ansible web -i inventory -m shell -a "df -h" -u bob -k


=========================
With ansible.cfg


ansible web -m ping -k

ansible web -m shell -a "df -h" -k

ansible web -m copy -a "src=f1.txt dest=/tmp/app.conf" -k



Component	Purpose

ssh-keygen	Passwordless login
inventory	List of target servers
ansible.cfg	Default Ansible settings




What ansible.cfg does

ansible.cfg has nothing to do with SSH key generation.

It tells Ansible things like:

[defaults]
inventory=inventory
remote_user=bob
host_key_checking=False

Meaning:

Which inventory file to use
Which user to connect as
Whether to check host fingerprints

=======================
Without ansible.cfg
======================

You must tell Ansible where the inventory is

ansible web -i inventory -m ping

================
With ansible.cfg
=================

ansible web -m ping
