Scenerio-Real time
===============
Your e-commerce application gets huge traffic during a sale.

Initially:

2 Pods
      ↓
CPU Usage = 30%

======
Suddenly thousands of users come.

2 Pods
      ↓
CPU Usage = 85%


=========
HPA detects high CPU and automatically creates more pods.

2 Pods → 4 Pods → 6 Pods


========
When traffic drops:

6 Pods → 3 Pods → 2 Pods


This saves cost and prevents application crashes.

Step 1: Deployment


apiVersion: apps/v1
kind: Deployment
metadata:
  name: springboot-app
spec:
  replicas: 2
  selector:
    matchLabels:
      app: springboot-app
  template:
    metadata:
      labels:
        app: springboot-app
    spec:
      containers:
      - name: springboot-app
        image: myrepo/springboot-app:v1
        ports:
        - containerPort: 8080

        resources:
          requests:
            cpu: "200m"
            memory: "256Mi"

          limits:
            cpu: "500m"
            memory: "512Mi"

Step 2: Create HPA

apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: springboot-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: springboot-app

  minReplicas: 2
  maxReplicas: 10

  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 70

We create a temporary BusyBox pod and continuously send requests to the application service using a while loop with wget. This generates load on the application, allowing us to test HPA behavior and observe Kubernetes automatically scaling pods based on CPU or memory utilization.
