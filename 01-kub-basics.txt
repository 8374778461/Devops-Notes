Components :

1. API Server
2. Controller 
3. Schedular 
4. ETCD 

1. API Server
   - Entry point of Kubernetes cluster.
   - Receives all requests.

2. Scheduler
   - Assigns pods to worker nodes.

3. Controller Manager
   - Ensures desired state matches current state.

4. ETCD
   - Key-value database storing cluster information.

1. Kublet:
=================
 running on every worker node.

Responsibilities:

Talks to API Server
Creates pods on the node
Monitors pod health
Sends node status to Control Plane

Example

You create pod:

kubectl run nginx --image=nginx

API Server
    ↓
Kubelet
    ↓
Creates Nginx Pod

=======================
2. Container run time Interface :CRI (Container Runtime Interface) is a standard interface that allows Kubelet to communicate with container runtimes such as containerd and CRI-O,
==========================

When you create a pod:

kubectl run nginx --image=nginx

Kubelet sends requests like:

Pull Image
Create Container
Start Container
Stop Container
Delete Container

These requests go through CRI to the runtime.

Kubelet
|
| "Start nginx container"
↓
CRI
↓
containerd
↓
Nginx Container Running

===========
3. Containered :
==============

containerd is a container runtime installed on worker nodes. It is responsible for pulling images and creating, starting, and stopping containers. Kubelet communicates with containerd through the Container Runtime Interface (CRI).

What containerd does?

✅ Pulls images from Docker Hub/ECR

✅ Creates containers

✅ Starts containers

✅ Stops containers

✅ Deletes containers


✅ containerd is a Container Runtime.
 ✅ CRI is the interface.
 ✅ Kubelet talks to containerd through CRI

=================
4. Kube-Proxy
==================

👉 Handles networking inside the cluster.

Responsibilities:

Service communication
Pod-to-Pod communication
Load balancing requests

========================
Docker Vs Containered :
====================

Docker is a complete container platform used by developers,
whereas containerd is the container runtime that actually
creates and manages containers. Docker internally uses
containerd, and Kubernetes communicates directly with
containerd through CRI.

Docker → containerd → runc → Container
Kubelet → CRI → containerd → runc → Container

Kubernetes only wants:

✅ Pull Image
✅ Create Container
✅ Start Container
✅ Stop Container

containerd can do all these jobs.

So Docker became an extra layer:

↓

Kubernetes developers removed that extra dependency and now use:

===
ctr
===

ctr means Containerd CLI (Command Line Interface)

Docker Runtime      → docker command
Containerd Runtime  → ctr command

Docker

docker images
docker ps
docker run nginx

Containerd

ctr images ls
ctr containers ls
ctr tasks ls

ctr is the native command-line tool for containerd. It is used to pull images, create containers, and manage containerd directly.


| Feature             | CTR                        | CRI                           | CRICTL                           |
| ------------------- | -------------------------- | ----------------------------- | -------------------------------- |
| Full Form           | Containerd CLI             | Container Runtime Interface   | CRI Command Line Tool            |
| Type                | Command-line tool          | Interface/Protocol            | Command-line tool                |
| Used By             | Admins                     | Kubernetes (Kubelet)          | Kubernetes Admins                |
| Purpose             | Manage containerd directly | Connect Kubernetes to runtime | Troubleshoot runtime through CRI |
| Is it a command?    | ✅ Yes                      | ❌ No                          | ✅ Yes                            |
| Talks to            | containerd                 | containerd, CRI-O             | CRI                              |
| Kubernetes uses it? | ❌ No                       | ✅ Yes                         | ❌ No                             |
| Common Commands     | `ctr images ls`            | No commands                   | `crictl ps`                      |
| Mostly Used For     | Containerd management      | Runtime communication         | Kubernetes troubleshooting       |

CTR is a containerd command-line tool used to manage containers directly. CRI is the interface used by Kubelet to communicate with container runtimes such as containerd. CRICTL is a command-line tool that communicates with the container runtime through the CRI interface and is mainly used for Kubernetes troubleshooting.

kubectl manages Kubernetes resources such as Pods, Deployments, and Services. ctr manages containers directly in containerd. While both can ultimately result in containers running, kubectl operates at the Kubernetes level, whereas ctr operates at the container runtime level.

kubectl → Cluster Level

| Item           | What is it?           | Who uses it?     | Purpose                            |
| -------------- | --------------------- | ---------------- | ---------------------------------- |
| **kubectl**    | CLI Command           | Kubernetes Admin | Manage Pods, Deployments, Services |
| **ctr**        | CLI Command           | Containerd Admin | Manage containerd directly         |
| **crictl**     | CLI Command           | Kubernetes Admin | Troubleshoot containers/runtime    |
| **CRI**        | Interface (Not a CLI) | Kubelet          | Communicates with containerd       |
| **containerd** | Runtime               | Kubernetes       | Runs containers                    |
| **Docker**     | Container Platform    | Developers       | Build and run containers           |
| **runc**       | Low-level Runtime     | containerd       | Actually creates container process |




containerd = Runtime installed on worker node

ctr = CLI used to access containerd

CRI = Interface used by Kubelet to access containerd

crictl = CLI used to access containerd through CRI

containerd is the software that actually pulls images, creates containers, starts containers, stops containers, and manages containers.

kubectl  → Manage Kubernetes resources

CRI      → Bridge between Kubelet and containerd

containerd → Container Runtime

ctr      → Directly manage containerd

crictl   → Troubleshoot containerd through CRI
