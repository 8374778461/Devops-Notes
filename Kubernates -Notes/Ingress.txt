Ingress is a Kubernetes resource used to expose multiple services through a single external URL or domain name.
 It acts as a traffic router and sends requests to the appropriate service based on host names or URL paths.

Pod runs the application, 
Service exposes the Pods, and 
Ingress exposes multiple Services using a single domain name and 
routes traffic to the correct application.


======================
1. manifest.yaml(java -web-app) with Cluster IP
============================================

apiVersion: apps/v1
kind: Deployment
metadata:
  name: javawebappdeployment

spec:
  replicas: 1

  strategy:
    type: Recreate

  selector:
    matchLabels:
      app: javawebapp

  template:
    metadata:
      name: javawebapppod
      labels:
        app: javawebapp

    spec:
      containers:
      - name: javawebappcontainer
        image: ashokit/javawebapp
        ports:
        - containerPort: 8080

---
apiVersion: v1
kind: Service

metadata:
  name: javawebappsvc

spec:
  type: ClusterIP

  selector:
    app: javawebapp

  ports:
  - port: 80
    targetPort: 8080

=================
Ingress Controller :
==================

Ingress only contains routing rules such as host-based or path-based routing. 
It cannot process traffic by itself. An Ingress Controller is required to read those rules and route incoming requests to the appropriate Kubernetes services. Popular Ingress Controllers include NGINX Ingress Controller and AWS Load Balancer Controller.

Ingress is map the   traffic to external urls  based on host / path  routing to services 

Ingress is a Kubernetes resource that routes external traffic to Kubernetes Services based on host-based routing or path-based routing.

Host-Based Routing and Path-Based Routing are two ways Ingress decides where to send traffic.
========================
1. Host-Based Routing
=====================

Routing based on the domain name (host).

Example

employee.company.com  → employee-service

admin.company.com     → admin-service

payroll.company.com   → payroll-service
``

User
 |
employee.company.com
 |
Ingress
 |
employee-service
 |
Pods
``

✅ Different DNS names
 ✅ Different applications


================
2. Path-Based Routing
=====================

Routing based on the URL path

company.com/employee → employee-service

company.com/admin    → admin-service

company.com/payroll  → payroll-service


User

 |
Ingress
 |
admin-service
 |
Pods

✅ Single DNS name
 ✅ Multiple applications

            port:
              number: 80

      - path: /maven
